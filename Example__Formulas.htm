示例：公式

 

W与常规数据绑定相比，公式为您提供了更多关于数据的控制。基本上，公式只是为控件定义的匿名函数，并在特定条件下执行。让我们来看看 Layout_CGGalleryEntry：

 

{

"类型": "ui.FreeLayout",

"方向": "vertical",

"预加载": {

"graphics": [

{ "路径": ($ -> [$tempFields.selectedImage]), "图像": ($ -> o)},

{ "路径": ["locked"], "图像": ($ -> o)}

]

},

"框架": [0, 0, Graphics.width, Graphics.height],

"控件": [

{

"类型": "ui.Image",

"框架": [0, 0],

            "公式": [$ -> o.image = $tempFields.selectedImage],

"动作": { "名称": "executeFormulas", "参数": [$ -> $backButton.visible = !$backButton.visible] }

},

{

"类型": "ui.Button",

"id": "backButton",

"参数": { "文本": { "lcId": "B0FD4BF121D9E44E7589CDD35869F86F2227", "defaultText": "返回" }, "动作": { "名称": "previousLayout" } },

"框架": [Graphics.width - 170, Graphics.height - 65, 150, 45],

"order": 1

}

]

}

 

正如我们所见，公式使用 formulas 属性定义，它是一个数组，接受多个公式并同步地逐个执行。在此示例中，公式将对象的 image 属性设置为 $tempFields.selectedImage，其中包含 CGGallery 中选择的图像的名称，以便全屏显示。虽然这种情况也可以通过常规数据绑定解决，但更复杂的情况则不能。此外，公式比常规数据绑定更快。

 

公式使用 $ 符号定义，它实际上只是一个快捷方式：

 

new ui.Formula( <function> )

 

但是，建议使用定义的 $ 函数：

 

window.$ = (f, data, event) -> new ui.Formula(f, data || null, event || null)

 

虽然 f 参数是要执行的函数，但其他两个参数是可选的。查看游戏内 UI API 参考了解更多信息。您还会看到公式可以在 formulas 属性之外的其他地方使用。

 

然而，现在一个问题是，如果公式比数据绑定更强大和更快，为什么数据绑定仍然存在？嗯，数据绑定对初学者来说更容易理解，而且有些情况用公式不容易解决。一个例子是我们之前在动画示例中使用的基本动画“changeTo”。它接受一个绑定表达式而不是一个公式，动画能够读写该字段（查看 ui.Component_BindingHandler）。如果我们在这里指定一个公式，则需要定义两个公式：一个用于读取值，一个用于写入值。使用数据绑定，我们可以只指定一个字段名即可完成，这使得它更容易使用，特别是对初学者而言。
