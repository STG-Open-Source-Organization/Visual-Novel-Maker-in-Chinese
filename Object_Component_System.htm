对象组件系统

 

对象组件系统V

 

N Maker 的实际视觉小说引擎构建在 Basic Engine 之上，它使用对象组件系统（OCS）设计，以保持事物更易于扩展和维护。

 

对于初学者来说，可能很难理解 VN Maker OCS 的实际优缺点，因此我们将更多地关注如何使用 VN Maker OCS。随着时间的推移，您将对其有更好的感觉。

 

游戏对象

 

在 VN Maker 的 OCS 中，整个游戏被划分为所谓的“游戏对象”，您可能以前听说过这个术语。每个游戏对象都代表当前游戏的特定部分。例如：背景是一个游戏对象，当前角色是一个游戏对象，消息框是一个游戏对象，依此类推。一个游戏对象也可以包含其他游戏对象。

 

组件

 

游戏对象本身不实现任何游戏特定的逻辑或行为，因为这些来自动态添加到它的“组件”。组件实现特定的功能，例如：在屏幕上渲染/显示对象，角色的行为等。在大多数情况下，组件的创建目标是独立性和可重用性。

 

一个游戏对象知道它附加的所有组件，一个组件知道它所附加的游戏对象。一个组件只能是某个具体游戏对象的一部分。如果游戏对象被销毁，它附加的所有组件也会被销毁。

 

属性

 

除了组件之外，游戏对象还可以有一组属性，这些属性也可以看作是一种组件。主要的区别在于属性是被动的，大多数情况下只是存储数据并定义游戏对象的当前状态。如果属性对多个独立组件有意义，则应将其添加到游戏对象。

 

创建游戏对象

要创建一个新的游戏对象，我们可以创建一个 gs.Object_Base 类的实例，然后我们可以添加组件和属性，如下例所示：

 

###* * 准备场景的所有视觉游戏对象。 ### prepareVisual: -> # 创建一个新的游戏对象 @gameObject = new gs.Object_Base() # 使其可见 @gameObject.visible = yes # 无偏移 @gameObject.offset = new gs.Point(0, 0) # 左上角原点 @gameObject.origin = new gs.Point(0, 0) # 设置屏幕上正方形的位置和大小。 @gameObject.dstRect = new gs.Rect(0, 0, 100, 100) # 设置正方形的颜色。 @gameObject.color = new gs.Color(255, 0, 0, 255) # 添加一个四边形组件到游戏对象。四边形组件在屏幕上显示 # 游戏对象为一个正方形/四边形。 @gameObject.addComponent(new gs.Component_Quad()) # 将游戏对象添加到场景 @object.addObject(@gameObject) # 我们已经完成了准备视觉对象的工作。因此，我们可以开始 # 场景过渡，以便我们的新创建的对象能够平滑淡入。 @transition()

 

如果我们测试这个示例，我们将看到屏幕左上角有一个红色的正方形。这仅仅是因为我们向游戏对象添加了一个 gs.Component_Quad 组件以及一个颜色属性和其他一些必要的属性。四边形组件扩展了 gs.Component_Visual 并被视为一个可视化组件，意味着它为游戏对象添加了显示自身的功能。

 

更详细地说：四边形组件访问游戏对象的颜色属性，并使用 Basic Engine 的 gs.Quad 对象在屏幕上显示它。如果您查看 gs.Component_Quad 脚本，您会发现它是一个非常简单的组件。

通过 @object，我们访问了当前场景，它本身就是一个游戏对象。如果我们查看我们测试平台的类定义，我们会看到这个：

class Component_TestBedBehavior extends gs.Component_SceneBehavior

 

正如我们所见，我们的测试平台实际上是一个组件。这是因为场景也是一个游戏对象，是游戏的根游戏对象。所有其他游戏对象，如角色、背景等，都属于它。

 

每个组件都有一个指向其游戏对象的引用，称为“@object”。因此，通过“@object.addObject”，我们将新创建的游戏对象添加到根游戏对象，即当前场景。这非常重要，因为否则，我们的游戏对象将不属于当前游戏，它不会被更新，因此不会在屏幕上可见。

 

定义一个游戏对象模板类

 

即使我们最后的示例到目前为止运行良好，但它存在一些问题：首先，每次我们想创建一个红色正方形时添加所有这些属性并不方便。嗯，也许可以使用工厂模式来解决，但还有一个问题：gs.Object_Base 实际上没有定义颜色属性以及我们设置的所有其他属性。我们只是动态地将这些属性添加到游戏对象，这由于 JavaScript / CoffeeScript 的特性不成问题。

 

在其他编程语言中，像这样的事情是不可能的，即使在 JavaScript / CoffeeScript 中，这种方法也会阻止 JIT 优化并降低性能。建议创建一个自己的类，该类扩展 gs.Object_Base 并定义所有必需的属性，还可以选择性地实例化必要的组件。您可以将该类定义想象成一个游戏对象模板。

 

上面的示例只是为了说明行为和视觉表示本身并不在游戏对象的类中实现，而是分布在多个独立的组件中。

所以，接下来让我们创建一个自己的游戏对象模板，以便更容易地在屏幕上显示正方形。首先，我们需要在“Objects”文件夹中添加一个名为“Object_Square”的新脚本。我们将以下代码放在里面：

# 定义一个继承自 gs.Object_Base 并用作 # 正方形游戏对象模板的新类。 class Object_Square extends gs.Object_Base constructor: (color) -> super # 使其可见 @visible = yes # 无偏移 @offset = new gs.Point(0, 0) # 左上角原点 @origin = new gs.Point(0, 0) # 设置屏幕上正方形的位置和大小。 @dstRect = new gs.Rect(0, 0, 100, 100) # 设置正方形的颜色。 @color = color # 添加一个四边形组件到游戏对象。四边形组件在屏幕上显示 # 游戏对象为一个正方形/四边形。 @addComponent(new gs.Component_Quad()) gs.Object_Square = Object_Square

因此，我们定义了一个新的类 Object_Square 并继承自 gs.Object_Base。在构造函数中，我们接受正方形颜色作为参数，并仅定义所有必需的属性，还添加了四边形组件。现在我们回到我们的测试平台组件并稍微更改 prepareVisual：

###* * 准备场景的所有视觉游戏对象。 ### prepareVisual: -> # 创建一个新的游戏对象 @gameObject = new gs.Object_Square(new gs.Color(255, 0, 0)) # 将游戏对象添加到场景 @object.addObject(@gameObject) # 我们已经完成了准备视觉对象的工作。因此，我们可以开始 # 场景过渡，以便我们的新创建的对象能够平滑淡入。 @transition()

 

这样看起来好多了，也更舒适了。我们只需要创建一个新的 gs.Object_Square 对象，传入我们想要的颜色，然后将其添加到我们的场景中，就这样。

 

使用现有的游戏对象和组件类

VN Maker 提供了一系列游戏对象和组件类，构成了实际的视觉小说引擎。它为背景、角色、消息等提供了游戏对象模板。在下面的示例中，我们将设置一个非常简单的场景，其中包含一个背景、一个角色和一个消息。

###* * 准备场景的所有视觉游戏对象。 ### prepareVisual: -> # 创建一个新的背景对象 @backgroundObject = new vn.Object_Background() # 设置背景图像 @backgroundObject.image = "Bench_Morning" # 初始化游戏对象 @backgroundObject.setup() # 在数据库中获取 ID 为 0006 的角色数据 characterData = RecordManager.characters[5] # 创建一个新的角色对象。我们将角色数据传递给它。 @characterObject = new vn.Object_Character(characterData) # 我们将表情设置为数据库中定义的角色的默认表情。 @characterObject.expression = RecordManager.characterExpressions[characterData.defaultExpressionId] # 初始化游戏对象。 @characterObject.setup() # 将角色在 x 轴上居中 @characterObject.dstRect.x = (Graphics.width - @characterObject.dstRect.width) / 2 # 手动更新角色对象，以便在场景 # 可见之前应用最新更改。 @characterObject.update() # 创建一个黑透明的消息背景对象 @messageBackgroundObject = new gs.Object_Square(new gs.Color(0, 0, 0, 160)) # 设置 z-index 为 800，以确保它显示在背景 + 角色的上方 @messageBackgroundObject.zIndex = 800 # 设置位置和大小。我们将其放置在屏幕底部。 @messageBackgroundObject.dstRect.set(0, Graphics.height - 150, Graphics.width, 150) # 初始化消息背景对象。 @messageBackgroundObject.setup() # 创建一个消息对象来在屏幕上显示消息。 @messageObject = new ui.Object_Message() # 设置消息的位置和大小 @messageObject.dstRect.set(0, Graphics.height - 150, Graphics.width, 150) # 初始化消息对象。 @messageObject.setup() # 向消息对象添加一条消息 @messageObject.behavior.addMessage("嘿！你好吗？", null, no, yes) # 将背景对象添加到场景 @object.addObject(@backgroundObject) # 将角色对象添加到场景 @object.addObject(@characterObject) # 将消息背景对象添加到场景 @object.addObject(@messageBackgroundObject) # 将消息对象添加到场景 @object.addObject(@messageObject) # 我们已经完成了准备视觉对象的工作。因此，我们可以开始 # 场景过渡，以便我们的新创建的对象能够平滑淡入。 @transition() ###* * 准备场景的所有数据并加载必要的图形和音频资源。 ### prepareData: -> # 加载背景图像 ResourceManager.getBitmap("Graphics/Backgrounds/Bench_Morning") # 加载角色表情图像 ResourceManager.getBitmap("Graphics/Characters/JaneDate_Normal")

 

如上所示，可以使用 vn.Object_Background 轻松创建背景，只需将 image 属性设置为背景名称即可。可以使用 vn.Object_Character 类添加角色，使用 ui.Object_Message 添加消息。我们还使用了我们之前创建的自定义游戏对象模板 gs.Object_Square 来显示消息的暗背景，以提高可读性。

 

游戏对象之间的通信

###*
* 准备场景的所有视觉游戏对象。
###  
prepareVisual: ->
    # 创建一个彩色方块对象
    @squareObject = new gs.Object_Square(new gs.Color(255, 0, 0))
    # 将其放置在游戏窗口的中心
    @squareObject.dstRect.set((Graphics.width - 100) / 2, (Graphics.height - 100) / 2, 100, 100)
    # 初始化游戏对象。
    @squareObject.setup()
    
    # 创建一个热点对象来捕获用户的鼠标点击。
    @hotspotObject = new ui.Object_Hotspot()
    # 将热点放置在与方块对象相同的位置和相同的大小。
    @hotspotObject.dstRect.set((Graphics.width - 100) / 2, (Graphics.height - 100) / 2, 100, 100)
    # 注册“click”消息/事件。events属性是事件发射器组件的快速访问器。
    @hotspotObject.events.on "click", =>
        # 如果热点被点击，我们将方块的颜色更改为蓝色
        @squareObject.color = new gs.Color(0, 0, 255)
    # 初始化热点对象
    @hotspotObject.setup()
    
    # 将方块对象添加到场景
    @object.addObject(@squareObject)
    # 将热点添加到场景。
    @object.addObject(@hotspotObject)

我们使用自定义的gs.Object_Square游戏对象在屏幕上显示一个红色的方块。然后我们添加一个热点，这是一个响应鼠标活动的区域，并将其放置在红色方块上方。我们的场景对象然后注册我们热点对象的“click”消息，因此当热点被点击时，回调函数将被调用，并将方块颜色设置为蓝色。因此，如果我们测试游戏并点击红色方块，它就会变成蓝色。

 

然而，上述方法有一个缺点，就是两个游戏对象需要相互了解。场景对象需要能够访问热点对象，以便它能注册“click”消息。这会在这两个游戏对象之间产生依赖关系，在某些情况下这是完全可以的，但在其他情况下我们需要保持事物更独立。

 

这时gs.GlobalEventManager就派上用场了，它本身就是一个全局的gs.Component_EventEmitter对象。全局事件管理器充当两个或多个游戏对象之间的通知中心，这样游戏对象就不再需要直接相互了解。例如：一个游戏对象想要发送一条消息，表明它被用户点击了。但它不会通知某个已注册的游戏对象，而是直接告诉全局事件管理器它已被点击，然后全局事件管理器将通知所有对此类消息感兴趣的游戏对象。

###*
* 准备场景的所有视觉游戏对象。
###  
prepareVisual: ->
    # 创建一个彩色方块对象
    @squareObject = new gs.Object_Square(new gs.Color(255, 0, 0))
    # 将其放置在游戏窗口的中心
    @squareObject.dstRect.set((Graphics.width - 100) / 2, (Graphics.height - 100) / 2, 100, 100)
    # 初始化游戏对象。
    @squareObject.setup()
    
    # 创建一个热点对象来捕获用户的鼠标点击。
    @hotspotObject = new ui.Object_Hotspot()
    
    # 将热点放置在与方块对象相同的位置和相同的大小。
    @hotspotObject.dstRect.set((Graphics.width - 100) / 2, (Graphics.height - 100) / 2, 100, 100)
    # 注册“click”消息/事件。events属性是事件发射器组件的快速访问器。
    @hotspotObject.events.on "click", (sender) =>
        # 通过全局事件管理器触发一个事件
        gs.GlobalEventManager.emit "hotspotClicked", sender
    # 初始化热点对象
    @hotspotObject.setup()
    
    # 注册“hotspotClicked”消息
    gs.GlobalEventManager.on "hotspotClicked", (sender) =>
        # 如果热点被点击，我们将方块的颜色更改为蓝色
        @squareObject.color = new gs.Color(0, 0, 255)
    
    # 将方块对象添加到场景
    @object.addObject(@squareObject)
    # 将热点添加到场景。
    @object.addObject(@hotspotObject)
    
    # 我们已经完成了准备视觉对象。因此，我们可以开始
    # 场景过渡，以平滑地淡入我们新创建的对象。
    @transition()

在上面的例子中，我们可以看到现在我们的场景对象得到了通知，而无需直接了解热点对象，因为通信是通过gs.GlobalEventManager进行的。因此，热点对象和场景对象双方都不需要相互了解。当感兴趣的游戏对象的类型和数量不确定，并且这些游戏对象无法访问或彼此没有了解时，这种通信方式很有用。

 

但是，不应该滥用上述方法作为标准的通信方式，因为其缺点是，无论消息来自哪个游戏对象，注册了全局事件管理器的一个游戏对象都会收到通知。对于一个简单的“click”消息，我们的场景对象会收到关于每次点击的消息通知，不仅来自面板对象，还来自任何通过全局事件管理器发送“click”消息的游戏对象。
