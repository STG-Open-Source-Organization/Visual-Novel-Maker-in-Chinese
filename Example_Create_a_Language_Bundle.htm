示例：创建语言包

 

I在这个例子中，我们将创建一个语言包，将我们的扩展翻译成另一种语言。为此，我们在“语言包”上单击鼠标右键，然后选择新建 > 语言包。我们将它命名为“CardExtension”。

 

{ "phrases": { "D63591732C7F724D8D98B6E5B34B914FFFD6": "示例文本" } }

 

它包含一个我们可以删除的示例短语。接下来，我们将创建另一个名为“CardExtension.de”的语言包。“CardExtension”包包含我们默认语言的短语。“默认语言”用于当前语言没有可用翻译时。第二个包“CardExtension.de”使用后缀“.de”，代表德语。因此，如果当前语言是德语，则使用该包。

 

让我们看看属性：

 

  • phrases

包含键：短语对，用于定义包的不同短语。因此，每个短语都需要一个唯一的键。键可以是任何文本，只要它足够独特即可。默认情况下，UID 用于每个短语。

要在 UI 视图中使用短语，您只需使用语法 $$<bundle>.<phrase_uid>，例如“$$CardExtension.D63591732C7F724D8D98B6E5B34B914FFFD6”。这种语法可以在大多数可以指定显示文本的地方使用。例如：

 

{

"type": "GSLabel",

"text": "$$CardExtension.D63591732C7F724D8D98B6E5B34B914FFFD6",

"frame": [0, 0]

}

 

因此，如果存在该键的短语，此标签将显示键“D63591732C7F724D8D98B6E5B34B914FFFD6”的短语。它首先检查当前语言是否存在该短语，如果不存在，则使用默认语言的短语。

 

要创建新短语，我们可以直接在我们的包中手动添加它们，但由于一段时间后这感觉有点不舒服，因此有两个辅助函数会自动完成大部分工作。这两个函数是“插入新字符串”和“插入新字符串 (LCS)”。我们可以在菜单栏的“工具 > 开发者工具”下找到这些函数，或者在 Extension Editor 的工具栏中找到它们。

 

这两个函数实际上做的是同一件事，但输出的格式不同。让我们看看这些函数如何让我们的生活变得更轻松：

 

首先，我们需要选择我们想要翻译的视图/场景命令/脚本中的一段文本。接下来，我们单击“插入新字符串”，它会要求我们输入一个包名。我们将输入我们的包名“CardExtension”，然后单击“确定”。现在发生了两件事：

 

1. 选定的文本已自动替换为“$$CardExtension.<uid>”。

2. 选定的文本已添加到默认语言的 CardExtension 包中，并且 UID 也已自动生成。

 

这为我们节省了大量时间，因为每次我们想翻译某些内容时，都不再需要自己生成 UID 并手动将短语添加到包中。我们可以只使用其中一个辅助函数。另一个辅助函数“插入新字符串 (LCS)”做的事情相同，但输出是：

 

lcs('<bundle>.<uid>')

 

如果需要，可以在脚本和公式中使用。
