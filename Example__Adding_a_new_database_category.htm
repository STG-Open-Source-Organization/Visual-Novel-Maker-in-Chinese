示例：添加新的数据库类别


I在以下示例中，我们想向编辑器的数据库添加一个新类别。为此，我们将首先通过菜单下的“视图 > 扩展”打开 Extension Editor。

 

接下来，我们将右键单击“数据记录视图”文件夹，然后选择“新建 > 数据记录视图”来为我们的新类别创建一个新视图。我们将它命名为“卡片”，因为我们想为我们的 VN 中的一个简单卡片游戏创建卡片。它已经包含了一些基本的 JSON，如下所示：

 

{

"category": "cards",

"descriptor": {

"name": "Cards",

"attribute": "cards",

"sections": []

}

}

 

让我们一步一步地介绍各个字段。

 

  • category

类别的后端字段名。它应该是一个唯一的驼峰式命名。

 

  • descriptor

包含有关用于类别中每个单独记录的视图的详细信息。

 

  • descriptor.name

显示在数据库类别列表中的名称。

 

  • descriptor.attribute

用于存储记录的后端属性名。该名称用于通过脚本访问数据记录。该名称应该是唯一的驼峰式命名。在大多数情况下，它与 category-field 相同。

 

  • descriptor.sections

包含用于 UI 的所有部分。

 

让我们先考虑一下我们需要存储什么样的数据来描述我们游戏中的一张卡片。我们将保持简单，所以一张卡片有一个名称、一个描述和一个图像，仅此而已。现在让我们为此设计 UI。

 

我们将创建两个部分。一个用于一般数据，如名称和描述，另一个用于图像。所以我们的 JSON 现在看起来像这样：

 

{

"category": "cards",

"descriptor": {

"name": "Cards",

"attribute": "cards",

"sections": [

{

"name": "General",

"items": [

]

},

{

"name": "Graphic",

"items": [

]

}

]

}

}

 

正如我们在这里看到的，我们添加了上面描述的两个部分。每个部分都有一个名称，显示给用户，以及一个项目列表，让用户可以与视图进行交互。

 

让我们从第一个部分“General”开始。在我们的例子中，我们只需要添加一个文本字段用于卡片名称和一个多行文本区域用于卡片的描述，再加上两个标签来为用户描述这些字段。所以我们的部分现在看起来像这样：

 

{

"name": "General",

"items": [

{

"type": "GSLabel",

"text": "Name:",

"group": "labels",

"frame": [0, 0]

},

{

"type": "GSTextField",

"attribute": "name",

"frame": [1, 0]

},

{

"type": "GSLabel",

"text": "Description:",

"frame": [0, 1]

},

{

"type": "GSTextField",

"multiline": true,

"attribute": "description",

"defaultValue": "Enter description here...",

"frame": [0, 2, -1, 100]

}

]

}

 

我们在部分中添加了 4 个项目。让我们更深入地研究每个项目字段。每个项目都可以有一些通用字段，这些字段适用于每种项目类型，也可以有一些特定于类型的字段。让我们从本例中使用的通用字段开始：

 

  • type (Required)

指示项目的类型，例如它是标签、文本字段、复选框等。必须存在该类型。

 

  • attribute

项目将存储其数据的后端 JavaScript 属性名。您可以使用该名称通过脚本访问数据。该名称对于视图应该是唯一的，以避免冲突。

 

  • frame (Required)

前两个值是位置，后两个值是项目的大小。对于大多数项目，大小会自动计算，但对于某些项目，至少需要指定高度，例如多行文本字段、表格等。您也可以使用 -1 作为大小值，表示值将自动计算。框架必须存在于每个项目，并且至少必须有一个 x 和 y 值。

 

  • defaultValue

您可以定义一个默认值，当创建新记录并且没有现有数据可读取时使用。

现在让我们看看本例中使用的特定于类型的字段。

 

  • group

将标签分配给一个标签组，该组会自动调整标签大小以正确适应，具体取决于其文本和同一组中其他标签的文本。例如，如果您有多个标签如下排列：

 

Label 1:         <Text-Field>

Other Label 2:   <Text-Field>

Another Label 3: <Text-Field>

 

您可能希望所有标签都具有相同的宽度，具体取决于具有最高宽度的标签，以避免您的布局看起来像这样：

 

Label 1: <Text-Field>

Other Label 2: <Text-Field>

Another Label 3: <Text-Field>

 

但是，这也可以通过使用不同类型的布局来解决，但这不在本教程的讨论范围内。查看Plugin API Reference以了解更多关于不同类型布局的信息。

 

  • multiline

指示我们想要一个多行文本字段。在这种情况下，我们必须为我们的文本字段指定一个高度值。在我们的例子中，我们将它设置为 100px。设置完第一个部分后，我们可以单击“预览”按钮来查看视图的交互式预览，以便我们可以检查我们的元素是否看起来正确。要关闭 DataRecordViews 的预览，只需再次单击“预览”按钮。

 

好的，让我们继续实现卡片图像的部分。

 

{

"name": "Graphic",

"items": [

{

"type": "GSImageView",

"attribute": "graphic",

"folder": "Graphics/Pictures",

"frame": [0, 0, 300, 450]

}

]

}

 

我们正在使用“GSImageView”，它允许用户选择一个图形并同时显示预览。我们使用 300x450 的尺寸，因为我们的卡片图像正好是那个尺寸。让我们看看字段：

 

  • folder

用于选择图像的文件夹。在我们的例子中，我们将使用图片文件夹“Graphics/Pictures”。

 

就是这样！我们完成了！现在让我们保存我们的项目并重新启动 Visual Novel Maker 来查看我们的更改。如果我们现在进入数据库，我们将看到我们新的“卡片”类别。我们现在可以使用该类别为我们的游戏创建不同类型的卡片。

 

通过脚本访问数据

在脚本中，我们可以使用 RecordManager 类来访问数据库。RecordManager 自动有一个属性，其名称与我们在数据记录视图的类别/属性字段中指定的名称相同。要以这种方式访问我们的卡片：

 

cards = RecordManager.cards

for card in cards

console.log("Name: #{card.name}")
