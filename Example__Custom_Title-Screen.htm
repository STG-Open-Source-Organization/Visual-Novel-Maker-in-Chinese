示例：自定义标题屏幕


I在这个例子中，我们将使用 Visual Novel Maker 的游戏内 UI 系统来创建自己的标题屏幕！

 

首先，我们需要打开脚本编辑器并打开“Layouts”文件夹，然后选择名为“Layout_Title”的脚本，该脚本包含标题屏幕的布局定义。

接下来，删除已有的内容，使脚本完全为空。然后我们将添加以下 JSON：

 

ui.UIManager.layouts.titleLayout = {

"type": "ui.FreeLayout",

"frame": [0, 0, Graphics.width, Graphics.height],

"items": []

}

 

如果我们现在测试播放我们的游戏，我们将看到我们的标题屏幕只是一个黑屏。这是因为我们还没有添加任何内容，我们只添加了一个空的布局。让我们一步一步来。

 

第一行总是这样的：

 

ui.UIManager.layouts.<unique_layout_name> = {

 

您不必完全理解这一行，唯一重要的是您需要为布局选择一个唯一的名称。该名称不应包含任何空格或特殊字符。名称用于将您的布局与其他布局连接，或使用场景命令“切换到布局”来显示您的布局。

 

在添加任何控件之前，我们总是必须至少定义一个布局，即主布局。在我们的例子中，它是一个 Free-Layout，允许我们自由地将控件定位在精确的位置。我们的布局有三个属性：

 

  • type

定义布局的类型。在我们的例子中是“ui.FreeLayout”。还有其他类型的布局可用，例如“ui.GridLayout”或“ui.StackLayout”。

 

  • frame

定义我们布局在屏幕上的位置和尺寸（以像素为单位）。前两个数字定义位置，在我们的例子中是屏幕的左上角 0,0。接下来的两个数字是布局的大小。我们在这里使用两个特殊的数字常量“Graphics.width”和“Graphics.height”，它们分别指当前屏幕的宽度和高度。所以我们的布局占满了整个屏幕。我们将在下面看到，也可以使用百分比值而不是像素坐标。

 

  • controls

该属性包含要显示的 UI 控件。由于我们还没有添加任何控件，所以我们得到一个黑屏。让我们在下一步中进行更改！

 

ui.UIManager.layouts.titleLayout = {

"type": "ui.FreeLayout",

"frame": [0, 0, Graphics.width, Graphics.height],

"controls": [

{

"type": "ui.Image",

"image": "bg-generic",

"frame": [0, 0, "100%", "100%"]

}

]

}

 

如果我们现在测试播放我们的游戏，我们将看到默认的背景图像“bg-generic”占据了整个屏幕。

 

让我们看看这个是如何工作的：

 

我们添加了一个类型为“ui.Image”的项目，顾名思义，它只是一个图像。让我们来看看属性：

 

  • type

控件的类型。在我们的例子中是“ui.Image”用于显示图像。但是还有许多其他控件类型可用，您甚至可以定义自己的控件模板，但我们将在另一个示例中介绍这一点。

 

  • image

我们要显示的图像资源的名称。默认情况下，资源必须位于 Graphics/Pictures 文件夹中。

 

  • frame

图像的位置和大小。我们将图像放在屏幕的左上角，对于大小，我们设置为“100%”，“100%”，它

将图像缩放到布局大小的 100%。在我们的例子中，它等同于 Graphics.width, Graphics.height。您可以尝试一下其他百分比，看看效果如何。您甚至可以进行计算并将像素值与百分比值混合，例如“100% - 250”。

 

在下一步中，我们将添加五个按钮用于以下标题屏幕选项：

 

  • 新游戏
  • 加载游戏
  • 退出

 

我们将使用堆栈布局将选项从上到下排序。

 

ui.UIManager.layouts.titleLayout = {

"type": "ui.FreeLayout",

"frame": [0, 0, Graphics.width, Graphics.height],

"controls": [

{

"type": "ui.Image",

"image": "bg-generic",

"frame": [0, 0, "100%", "100%"]

},

{

"type": "ui.StackLayout",

"orientation": "vertical",

"frame": ["35%", "60%", "30%", "30%"]

"controls": [

{

"type": "ui.Button",

"params": { "text": "新游戏" },

"resizable": true,

"margin": [0, 0, 0, 10]

},

{

"type": "ui.Button",

"params": { "text": "加载游戏" },

"resizable": true,

"margin": [0, 0, 0, 10]

},

{

"type": "ui.Button",

"params": { "text": "退出" },

"resizable": true,

"margin": [0, 0, 0, 10]

}

]

}

]

}

 

如果我们现在测试播放我们的游戏，我们将看到带有三个按钮的背景。

 

在图像之后，我们添加了一个新的垂直堆栈布局。如果我们看一下 frame 属性，我们只看到百分比值。正如我们之前看到的，您甚至可以使用百分比值作为 frame 属性，还可以进行计算，例如“50% - 20”。百分比值允许您在不知道确切屏幕或父布局尺寸的情况下定义位置和大小。

 

我们还将 orientation 属性设置为“vertical”，以便像堆栈一样垂直排列我们的按钮。我们为每个选项添加了三个按钮控件。让我们仔细看看：

 

{

"type": "ui.Button",

"params": { "text": "新游戏" },

"resizable": true,

"margin": [0, 0, 0, 10]

}

 

  • type

我们使用了“ui.Button”来创建一个按钮控件。实际上，“ui.Button”是在“Template_Button”脚本的“Templates”子文件夹中定义的模板。我们将在稍后的示例中处理模板。

 

  • params

由于“ui.Button”实际上是一个模板，我们可以使用“params”将数据传递给模板。在我们的例子中，我们只传递一个参数“text”，值为“New Game”给模板。我们不需要知道模板是如何处理这些数据的，我们只需要知道 text 定义了按钮的文本。

 

  • resizable

定义如果需要，我们的按钮是否可以由布局自动调整大小，因此我们无需指定 frame 属性。我们将其设置为 true，因此我们不必担心按钮的大小。

 

  • margin

margin 属性在按钮周围定义了空白区域。它可以用于在控件之间定义间隙，或者如果您只想稍微调整控件。边距值以像素为单位，定义为 [<left>, <top>, <right>, <bottom>]。因此，在我们的例子中，我们为每个按钮使用 10px 的底部边距。

 

让我们通过向按钮添加操作来完成此示例。操作描述了一段后台逻辑，将在单击按钮时执行。

 

ui.UIManager.layouts.titleLayout = {

"type": "ui.FreeLayout",

"frame": [0, 0, Graphics.width, Graphics.height],

"controls": [

{

"type": "ui.Image",

"image": "bg-generic",

"frame": [0, 0, "100%", "100%"]

},

{

"type": "ui.StackLayout",

"orientation": "vertical",

"frame": ["35%", "60%", "30%", "30%"]

"controls": [

{

"类型": "ui.Button",

"参数": { "文本": "新游戏", "动作": { "名称": "newGame" } },

"可调整大小": true,

"边距": [0, 0, 0, 10]

},

{

"类型": "ui.Button",

"参数": { "文本": "加载游戏", "动作": { "名称": "switchLayout", "参数": { "名称": "loadMenuLayout", "savePrevious": true } } },

"可调整大小": true,

"边距": [0, 0, 0, 10]

},

{

"类型": "ui.Button",

"参数": { "文本": "退出", "动作": { "名称": "quitGame" } },

"可调整大小": true,

"边距": [0, 0, 0, 10]

}

],

}

],

}

 

对于每个按钮，我们只需将一个新参数传递给按钮模板，称为“action”。一个动作有一个唯一的名称，并且可以选择包含一组参数。让我们来看看我们第一个按钮的动作：

 

"动作": { "名称": "newGame" }

 

通过这个，我们定义了点击按钮时应该执行“newGame”动作。该动作，顾名思义，启动一个新游戏。所以如果我们点击“新游戏”按钮，一个新的游戏就会开始。

 

接下来让我们看看我们第三个按钮“退出”：

 

"动作": { "名称": "quitGame" }

 

这很相似，这次我们只是执行一个不同的动作“quitGame”，它会退出游戏。

 

我们第二个按钮“加载游戏”的第二个动作看起来稍微复杂一些，但实际上与之前一样：

 

"动作": { "名称": "switchLayout", "参数": { "名称": "loadMenuLayout", "savePrevious": true } }

 

在这里，我们正在执行“switchLayout”动作，它会切换到“params”属性中指定的另一个布局。所以我们之前两个动作之间的区别在于我们必须指定传递给动作的一些数据。“switchLayout”期望以下参数：

 

  • 名称

我们要切换到的布局的名称。在我们的例子中是“loadMenuLayout”，这是加载菜单的布局定义的唯一名称。您可以在“Layout_LoadMenu”中看到这一点。

 

  • savePrevious

此参数是可选的，默认为 false。但如果设置为 true，则之前的场景，在我们的例子中是标题屏幕，不会被完全擦除，而是只是

暂停并隐藏。我们可以使用“returnToPrevious”动作返回到它。但这不包含在此示例中，我们只需将其设置为 true，以便在单击返回按钮时，加载菜单可以返回到标题屏幕。

 

现在我们的标题屏幕就完成了！
